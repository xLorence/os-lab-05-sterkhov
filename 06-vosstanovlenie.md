### Часть А. Находим «удалённый» пароль (работа команды rm)

```
daniil247@debian-vm:~$ sudo mount /dev/loop0p1 /mnt/data1
daniil247@debian-vm:~$ echo "ПАРОЛЬ_ОТ_БАЗЫ=Kr0kodil2026" | sudo tee /mnt/data1/secret.txt
ПАРОЛЬ_ОТ_БАЗЫ=Kr0kodil2026
daniil247@debian-vm:~$ sync
daniil247@debian-vm:~$ sudo rm /mnt/data1/secret.txt
daniil247@debian-vm:~$ sync
daniil247@debian-vm:~$ sudo umount /mnt/data1
daniil247@debian-vm:~$ sudo grep -a -o 'ПАРОЛЬ_ОТ_БАЗЫ=[A-Za-z0-9_]*' /dev/loop0p1
ПАРОЛЬ_ОТ_БАЗЫ=Kr0kodil2026
```
Вывод grep подтверждает, что после использования стандартной команды rm первый пароль всё ещё можно прочитать из сырых блоков диска.

### Часть Б. Уничтожаем правильно (работа утилиты shred)

```
daniil247@debian-vm:~$ sudo mount /dev/loop0p1 /mnt/data1
daniil247@debian-vm:~$ echo "ПАРОЛЬ_ОТ_БАЗЫ=Begemot2026" | sudo tee /mnt/data1/secret2.txt
ПАРОЛЬ_ОТ_БАЗЫ=Begemot2026
daniil247@debian-vm:~$ sync
daniil247@debian-vm:~$ sudo shred -u -z -n 3 /mnt/data1/secret2.txt
daniil247@debian-vm:~$ sync
daniil247@debian-vm:~$ sudo umount /mnt/data1
daniil247@debian-vm:~$ sudo grep -a -c 'Begemot2026' /dev/loop0p1
0
```

Вывод grep равен 0 — совпадений на диске больше нет, второй пароль успешно уничтожен.

### Ответы на контрольные вопросы:
1. Вывод grep, нашедший первый пароль после rm: `ПАРОЛЬ_ОТ_БАЗЫ=Kr0kodil2026`.
2. Вывод grep для второго пароля после shred: `0`.
- Что физически делает `rm`, а что — `shred`: Команда `rm` удаляет только запись о файле из таблицы файловой системы (inode) и помечает это место как свободное, оставляя сами физические данные нетронутыми до перезаписи новыми файлами. Утилита `shred` действует на физическом уровне: перед удалением файла она принудительно перезаписывает сектора, в которых он хранился, случайными данными и нулями, полностью стирая оригинальную информацию.
- Почему на SSD надёжнее с самого начала шифровать весь диск: Контроллер SSD постоянно перемещает данные по ячейкам памяти для их равномерного износа. При попытке перезаписать файл через `shred`, контроллер может записать нули в новые свободные ячейки, а ячейки с оригинальным паролем просто скроет из доступа ОС. При полном шифровании диска все данные изначально хранятся в виде нечитаемого шума, и для их мгновенного «уничтожения» достаточно стереть мастер-ключ.
- Вывод для практики: Перед передачей или утилизацией старого диска обычного форматирования недостаточно. Жёсткие диски (HDD) необходимо полностью затирать нулями (например, утилитой `dd` или `shred`). Для SSD следует использовать аппаратную команду Secure Erase через официальное ПО производителя, а при наличии критически важных данных — физически уничтожить носитель.
